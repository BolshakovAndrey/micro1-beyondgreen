# Воспроизведение — от чистого окружения до официального прогона

Русская версия судейского `docs/REPRODUCTION.md` для проверки владельцем. Английский
оставлен в командах, путях, идентификаторах и значениях полей.

**Версия оценки:** `eval-v1.1.0`
**Требования:** `EV-004`–`EV-010`, `NFR-001`–`NFR-009`, `AR-003`–`AR-007`

Это единственный путь от пустой машины до доказательств, на которых стоит каждое
утверждение README. Он разделяет то, что может повторить любой ревьюер, и то, что по
протоколу исполняется ровно один раз.

## Что воспроизводится, а что нет

| Уровень | Что даёт | Где работает | Вызовов модели |
|---|---|---|---|
| **A. Офлайн-повтор** | Пересобирает поданные доказательства и отвергает подмену | любая платформа | нет |
| **B. Полная локальная проверка** | Все фикстуры, изоляция и манифесты | только macOS | нет |
| **C. Официальный scored-прогон** | Результат бенчмарка на 20 кандидатах и двух плечах | macOS + аутентифицированный `codex` CLI | 20 |

Уровни A и B воспроизводятся ревьюером полностью, без учётных данных и без сети.
Уровень C — **create-once**: его output-корни нельзя перезаписать, удалить или
перегенерировать, а второй запуск был бы не повтором бенчмарка, а другим, нескоринговым
прогоном. Ревьюер подтверждает уровень C чтением неизменяемых доказательств и их
повтором, а не повторным исполнением.

## 1. Окружение

Node `22.22.3` (`.node-version`); поле `engines` требует `>=22.22.3 <23`. Зависимости
зафиксированы точными версиями и ставятся только из lockfile.

```bash
node --version          # v22.22.3
npm ci
npm run task -- list    # полный каталог задач с описаниями
```

Рабочие: `react` `19.2.8`, `react-dom` `19.2.8`, `@preact/signals-react` `3.12.0`,
`jsdom` `30.0.1`, `zod` `4.5.2`. Сборка и тесты: `typescript` `5.9.3` и `node:test`.
Ни на одном уровне нет тест-фреймворка, бандлера и сетевой зависимости.

**Граница платформы.** Изолирующий раннер запрещает сетевой выход через macOS
`/usr/bin/sandbox-exec` поверх модели разрешений Node. На других платформах он **падает
закрыто**: разрешающий fallback не зарегистрирован, потому что более слабая песочница,
которая всё равно рапортует успех, обесценила бы само утверждение об изоляции. Уровень A
платформонезависим.

## 2. Уровень A — детерминированный офлайн-повтор (любая платформа)

```bash
npm run task -- d01:replay
npm run task -- d01:replay
```

Оба вызова обязаны напечатать одинаковые digest'ы JSON и HTML. Ядро повтора проверяет оба
финализированных хэша решений, обе пары наблюдений, каждую привязку evaluator→decision,
каждое capability-доказательство раннера и воркера и сохранённый JSON по Zod-схеме — и
только потом пересобирает отчёт целиком в памяти. Оно не импортирует возможностей записи
в файловую систему, сети, подпроцессов, часов и случайности и отвергает подменённый отчёт.

## 3. Уровень B — полная проверка с чистого чекаута (macOS)

```bash
npm test
npm run task -- d01:verify
npm run task -- d01:demo
npm run task -- d01:replay
npm run task -- d02:verify
npm run task -- d03:verify
npm run task -- d04:verify
npm run task -- development:verify
npm run task -- held-out:verify
npm run task -- freeze:self-test
npm run task -- official:preflight
```

Каждая команда печатает единственный маркер успеха вида `TASK_PASSED <task>`; любой другой
выход — это отказ, и он никогда не пересказывается как успех. `d01:demo` записывает
судейский бандл в `artifacts/evaluation/BG-D01-VERTICAL-SLICE.{json,html}` и
`artifacts/evaluation/BG-D01-OFFLINE-REPLAY.jsonl`.

Что именно доказывает каждая команда — в [`REVIEWER_GUIDE.md`](REVIEWER_GUIDE.md); пути к
доказательствам D01, ожидаемые вердикты и ограничения — в
[`D01_REPRODUCTION.md`](D01_REPRODUCTION.md).

**Время.** На эталонной машине (Apple Silicon, macOS 24.6, Node 22.22.3) обычный набор
занимает около 25 секунд; команды среза D01 упираются в реальные запуски подпроцессов под
OS-песочницей и занимают по несколько секунд. Уровень B целиком — это минуты, не часы.

## 4. Уровень C — официальный scored-прогон

### Предусловия

1. Чистое рабочее дерево на проверенном коммите.
2. Локально аутентифицированный `codex` CLI: `codex login status` отвечает
   `Logged in using ChatGPT`. Замороженный адаптер — `codex-exec-jsonl-v1` против
   наблюдавшегося `codex-cli 0.148.0`, замороженная модель — `gpt-5.6-sol`. Ключевые
   учётные данные не используются, подменять модель нельзя: недоступность модели
   останавливает прогон, а не переключает его на молчаливую замену.
3. Одобренный владельцем session boundary в
   `artifacts/trajectories/session-boundaries/`, экспортированный как
   `MICRO1_OFFICIAL_SESSION_BOUNDARY` в формате `SES-YYYYMMDD-NNN`. Без него раннер не
   стартует.

### Команды

```bash
npm run task -- baseline:verify    --evaluation-version eval-v1.1.0
npm run task -- beyondgreen:verify --evaluation-version eval-v1.1.0
npm run task -- official:preflight

MICRO1_OFFICIAL_SESSION_BOUNDARY=SES-YYYYMMDD-NNN \
  npm run task -- evaluation:run --evaluation-version eval-v1.1.0

npm run task -- replay --evaluation-version eval-v1.1.0
```

Две команды `*:verify` проверяют замороженный контракт команд каждого плеча **без**
исполнения официального прогона. `official:preflight` проверяет замороженную опись 10×2 и
строит неисполняемый план на 20 слотов и два плеча.

### Ожидаемый вывод

При успехе `evaluation:run` печатает одну строку JSON:

```json
{"status":"OFFICIAL_EVALUATION_COMPLETED","evaluationVersion":"eval-v1.1.0",
 "slots":20,"armPlans":40,"captures":80,"observationPairs":40,"evidenceSha256":"…"}
```

При отказе — `OFFICIAL_EVALUATION_FAILED <причина>` и ненулевой код возврата. Сорвавшийся
прогон сохраняется, а не удаляется: восстановление продолжается от замороженных решений
командой `evaluation:recover-post-decision`, которой доступны сценарии, наблюдатели,
evaluator, агрегация и повтор — но никогда плечо и никогда модель.

### Что жёстко держит протокол

- 20 кандидатов × 2 плеча = 40 arm-планов, по одной попытке, ноль повторов.
- **Базовое плечо** принимает по компиляции и видимым легаси-тестам и делает **ноль**
  вызовов модели.
- **BeyondGreen** делает **ровно один** вызов модели на кандидата. Второй вызов, retry,
  таймаут или некорректный вывод дают операционный `abstain`, а не попытку починки.
- 180 с внешнего wall clock на кандидата; адаптеру отдаётся 165 с, а 15 с резервируются на
  проверку схемы, финализацию доказательств и чистое завершение.
- Кандидат хэшируется до и после каждого плеча; родитель открывает verifier-only байты
  только после того, как оба решения стали неизменяемыми, — именно это делает `K=0`
  проверяемым.
- Каждый кандидат наблюдается дважды; два канонических digest'а наблюдений обязаны
  совпасть, иначе прогон аннулируется до старта любого evaluator.

## 5. Время и стоимость

| Позиция | Значение |
|---|---|
| Вызовов модели за официальный прогон | 20 (только BeyondGreen) |
| Принудительный потолок на кандидата | 180 с wall clock / 165 с движку |
| Верхняя граница фазы плеч | 20 × 180 с ≈ 60 мин, если каждый кандидат выберет потолок |
| Уровни A и B | ноль вызовов модели, нулевая маржинальная стоимость |
| Модель оплаты | фиксированная подписка (CLI, аутентифицированный ChatGPT) |
| Маржинальные USD на кандидата | `not_measured` — никогда не ноль и никогда не оценка |
| Расход токенов | `not_measured`, пока CLI не отдаёт его явно и стабильно |
| Человеческое время | только время супервизии агента |

Потолок в USD не заявляется, и экономия времени против автоматического базового плеча не
заявляется: ручное время ревью не оценивается. Поля пофакторного учёта перечислены в
[`EVALUATION.md`](EVALUATION.md).

## 6. Проверки целостности

```bash
npm run task -- checksums:check
npm run task -- d01:manifests:check
npm run task -- d01:vertical:manifest:check
git diff --check
```

Неизменяемые манифесты проверяются рекурсивным перечислением авторизованного корня пакета
до того, как хоть одной записи манифеста начинают доверять; неперечисленные файлы,
симлинки, выходы за пределы пути, дубли объявлений и несовпадения digest'ов падают
закрыто. Clean-room сканы выполняются только через owner-controlled интерфейс
`micro1-safe-preflight`, значение и путь его denylist никогда не печатаются.

## 7. Состояние официального прогона

Фаза плеч завершена и заморожена, post-decision фаза оракула — нет. По записям в
`artifacts/evaluation/official/`:

| Корень | Состояние |
|---|---|
| `RUN-…-001` | pre-arm infrastructure failure; ноль решений, вызовов модели, captures и unblinding |
| `RUN-…-002` | 40 неизменяемых arm-записей — 20 status-quo (0 вызовов модели) и 20 BeyondGreen (по 1) |
| `…-POSTDECISION-002` | отказ на стадии observer до первой capture |
| `…-POSTDECISION-003` | частичный: 80/80 observer captures, все schema-valid, все 40 пар совпадают по digest; 8/40 evaluator records; нет aggregate, report и replay |

Каждый сорвавшийся и частичный корень сохранён побайтово как честное доказательство.
Поэтому scored-агрегатов пока не существует: ячейки метрик в README остаются пустыми,
пока завершённый post-decision корень не даст все 40 evaluator records из уже замороженных
решений. Плечи ради этого не перезапускаются.

## 8. Ограничения

- Бенчмарк синтетический, перенос на продакшн-репозитории не продемонстрирован.
- Версия 1 покрывает только миграцию React со state на сигналы.
- Уровни B и C требуют macOS; на других платформах изолирующий раннер падает закрыто.
- Официальный прогон — create-once. Ревьюер воспроизводит его повтором неизменяемых
  доказательств, а не повторным исполнением.
