# BG-H03 — русская карточка поведения и происхождения

**Статус:** текст подготовлен; ожидаются хеш координатора и отдельное одобрение владельца  
**Фикстура:** `BG-H03`, скрытый набор  
**Класс поведения:** устойчивость идентичности объекта  
**Граница работы:** `SES-20260830-010`

Это полный русский материал для владельца по английскому файлу
`evaluation/behavior-specs/BG-H03_BEHAVIOR.md`. Здесь не создано ни реализации,
ни кандидатов, ни тестов, ни скрытого эталона, ни исполняемого манифеста. Внутренние
необработанные события дочернего агента не считаются экспортированной трассой.

## Что именно предлагается зафиксировать

Синтетическая задача описывает стол выбора коллекции в общественной библиотеке
семян. Frontend-инженер проверяет уже существующую миграцию состояния React на
signals — сигналы, то есть реактивные контейнеры значения. Пользователь выбирает
коллекцию и отдельно редактирует заметку поиска. Нижестоящий просмотр получает
объект `SelectionHandle`, который обозначает выбранную коллекцию.

Риск состоит не в неверном тексте объекта, а в ненужной смене самой ссылки на него.
Если миграция создаёт новый равный по значениям объект при каждом постороннем
обновлении, зависимый просмотр повторно подключается. Обычные тесты, сравнивающие
только строки и выбранный идентификатор, этого не замечают.

## Зафиксированное наблюдаемое поведение

- На старте выбрана коллекция `herbs`, заметка пуста, создан ровно один объект и
  выполнено одно подключение просмотра.
- Изменения заметки на `spring` и `summer` сохраняют точно ту же ссылку на объект и
  не увеличивают счётчик подключений.
- Выбор `flowers` создаёт ровно один новый объект и даёт счётчик `2`.
- Изменение заметки на `autumn` не меняет этот объект.
- Повторный выбор уже выбранного `flowers` ничего не пересоздаёт.
- Возврат к `herbs` создаёт новый объект относительно объекта `flowers` и даёт
  счётчик `3`.
- `reset` очищает заметку, но не пересоздаёт уже подходящий объект `herbs`.
- Значения объекта неизменяемы, журнал действий детерминирован, внешняя сеть,
  часы, случайность и состояние машины не участвуют.

Будущие видимые тесты намеренно смогут проверять значения, подписи, журнал и сброс,
но не будут хранить ссылки между действиями и проверять лишние подключения. Оба
будущих кандидата обязаны компилироваться и проходить этот неизменный видимый набор.

Сохраняющий кандидат обязан удерживать объект, пока выбранный идентификатор не
изменился. Единственный разрешённый дефект ложно-зелёного кандидата — создание
равного по значениям нового объекта при постороннем обновлении или повторном выборе,
что вызывает лишнее подключение. Все прочие свойства он обязан сохранить.

## Происхождение и лицензии

Использована только общая идея идентичности из публичной страницы React
`https://react.dev/learn/preserving-and-resetting-state`; дата доступа для записи —
`2026-08-30`. Документация React только цитируется по адресу для ознакомления с
соблюдением авторских прав и правил сайта; её содержимое не перераспределяется.
Лицензия выбранного проекта Preact Signals зафиксирована по
`https://github.com/preactjs/signals/blob/main/LICENSE` как MIT. В этой задаче сеть
не использовалась: адреса взяты из разрешённых репозиторных источников.

Тексты примеров, код, структура компонентов и тесты не копировались. Область
библиотеки семян, действия, значения и отношения идентичности придуманы независимо.
Материал не связан ни с одним частным продуктом и не использует частные структуры,
названия или данные.

## Граница скрытого эталона

Позднее отдельный закрытый пакет проверяющего сможет хранить точные сравнения ссылок,
счётчики подключений и правильные метки кандидатов. Сейчас такого кода и данных нет.
До неизменяемого решения ни одна оцениваемая ветвь не должна иметь возможность
читать, перечислять или монтировать этот пакет. Правило `K=0` означает ноль подсказок
скрытого эталона до решения. Нарушение доступа, нехватка доказательств или
недетерминизм должны безопасно остановить оценивание.

## Риски, остановки и свидетельства этой волны

Ожидаемые ошибки: лишнее пересоздание объекта, лишнее подключение, устаревшие поля,
изменение старого объекта, отсутствие нового объекта при реальной смене выбора,
случайный сброс заметки и недетерминированное завершение эффектов.

Работу необходимо остановить при сомнительной лицензии, сходстве с запомненной
частной структурой, появлении внешнего пути или скрытого содержимого, необходимости
второго дефекта, невозможности сохранить видимые тесты зелёными или нарушении
границы эталона. В этой волне не было компиляции, тестов, предварительных проверок,
захвата трассы, вызовов модели, браузера, Chromium, commit или push. Первая попытка
структурно разобрать YAML остановилась до проверки данных: установленный Ruby/Psych
не поддерживает метод `safe_load_file`. Файлы не были изменены; выполнен один
эквивалентный повтор через `safe_load(File.read(...))`, результат которого передан
координатору.

Координатору ещё предстоит вычислить точные SHA-256, проверить разделение 4/6 и
взаимно-однозначное соответствие классов, выполнить обе безопасные предварительные
проверки и представить общий пакет владельцу. Одобрение этой карточки сможет
зафиксировать только текст и происхождение BG-H03. Оно не разрешит реализацию,
кандидатов, тесты, скрытый эталон, официальный или оцениваемый запуск, модель,
Chromium, commit или push.
