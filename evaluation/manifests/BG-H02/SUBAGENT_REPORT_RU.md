# BG-H02 — отчёт подагента о реализации сложного случая

## Объём и граница

Реализована только отложенная фикстура `BG-H02` класса `async_ordering` —
логический порядок асинхронных завершений. Её заранее объявленный статус сложного
случая сохранён в закрытой ground truth, итоговом manifest и самопроверке. Правила
чистого помещения, прочитанные контракты и запреты доступа совпадают с полным
перечнем в отчёте `BG-H01`; никакие внешние или приватные источники не читались.
Существующие freeze/provenance/owner-файлы и все shared-пути остались без изменений.

## Реализованное поведение

Публичный пакет содержит типизированный интерфейс управляемого отложенного
источника, harness, минимальную отрисовку и пять общих видимых проверок. Источник
создаёт ровно один handle — идентификатор управляемого запроса — на выбор и
завершается только явной командой harness; сеть, часы, `sleep`, случайность и
автоматические повторы отсутствуют.

Созданы ровно два нейтральных кандидата. Сохраняющее поведение связывает callback
завершения с монотонной логической эпохой и обесценивает старые callbacks при новом
выборе или `reset`. Единственная разрешённая ошибка второго варианта — отсутствие
этой проверки: любое успешное завершение записывает результат. Имена кандидатов и
их метки сопоставлены только внутри verifier-only — закрытого для оцениваемых
ветвей — пакета.

Канонический driver — исполнитель сценария — создаёт `R1`, затем `R2`, завершает
`R2` раньше `R1`, после чего создаёт `R3`, выполняет сброс и завершает `R3`.
Правильный вариант принят; вариант без epoch guard — проверки текущей логической
эпохи — отклонён уже на `complete-R1`. Видимые тесты используют только один запрос
или полностью последовательные запросы и поэтому честно сохраняют утверждённый
blind spot — намеренный пробел унаследованного тестирования.

Отдельные SHA-256 manifests фиксируют публичный пакет, закрытый пакет и каждого
кандидата. Итоговый manifest связывает реализацию с уже утверждёнными freeze,
описаниями и provenance, а также хранит `challenging_case=true`. Публичные и важные
TypeScript API документированы английским JSDoc; короткие английские комментарии
объясняют, почему логическая эпоха важнее времени завершения.

## Команды, результаты, ошибки и исправления

Последовательность команд, ранняя остановка Node 18, удалённый временный loader,
переход на утверждённый `v22.22.3`, compilation и capability-пробы полностью и
без необходимости читать отчёт BG-H01 перечислены ниже.

1. `npm run compile` — предварительно код `0` в исходном shell.
2. `node --import tsx --test evaluation/arm-visible/BG-H01/visible.test.ts evaluation/verifier-only/BG-H01/self-check.test.ts evaluation/arm-visible/BG-H02/visible.test.ts evaluation/verifier-only/BG-H02/self-check.test.ts`
   — остановка до тестов: Node `v18.16.1` не поддержал требуемый параметр.
3. Одна временная fixture-only попытка TypeScript loader на Node 18 остановилась до
   assertions с `ERR_REQUIRE_ESM` из-за несовместимости runtime с `jsdom@30.0.1`.
   Loader удалён; ни один manifest и кандидат не зависел от него.
4. `zsh -lic 'node --version'` — `v22.22.3`; нерелевантный shell-шум и машинный
   путь исключены из репозиторного отчёта.
5. `zsh -lic 'npm run compile'` — код `0` на утверждённом runtime.
6. `zsh -lic 'node --test evaluation/arm-visible/BG-H01/visible.test.ts evaluation/verifier-only/BG-H01/self-check.test.ts evaluation/arm-visible/BG-H02/visible.test.ts evaluation/verifier-only/BG-H02/self-check.test.ts'`
   — код `0`, `14/14`; для `BG-H02` пройдены `5/5` видимых assertions и `2/2`
   verifier-only самопроверки. Правильный вариант принят, единственный
   ложно-зелёный дефект отклонён на `complete-R1`.
7. Команда четырёх `node --permission` проб, полностью записанная в отчёте BG-H01,
   завершилась с кодом `0`. Для `BG-H02` публичный процесс получил
   `allDenied=true`, `errorProbeIndistinguishable=true`, `operationCount=4`;
   процесс оценщика получил `allCandidateAccessDenied=true`, `operationCount=3`.

8. После создания manifests структурный JSON-разбор и точный пересчёт файловых и
   пакетных SHA-256 завершились с кодом `0` и подтверждением
   `BG-H01_BG-H02_MANIFESTS_VERIFIED`.
9. Финальная объединённая команда `zsh -lic 'npm run compile && node --test
   evaluation/arm-visible/BG-H01/visible.test.ts
   evaluation/verifier-only/BG-H01/self-check.test.ts
   evaluation/arm-visible/BG-H02/visible.test.ts
   evaluation/verifier-only/BG-H02/self-check.test.ts'` завершилась с кодом `0`:
   compilation зелёная, повторно пройдены `14/14` тестов.

## Риски и запросы координатору

Детерминированность обеспечена явным завершением handles, а не таймерами. Смысловой
дрейф, oracle leakage — раскрытие закрытого эталона, — сомнительное происхождение
или изменение общей методики не обнаружены. Официальный/scored run, unblinding,
live product model, Claude, Chromium, browser/private MCP, общий preflight и push
не выполнялись. Необработанные внутренние события не называются экспортированной
трассой.

Координатору нужно будет отдельно включить `BG-H02` и его отметку сложного случая в
shared registry/tasks, общий checksum index и интеграционные проверки manifest,
детерминированного расписания и физической изоляции. Данный fixture-only commit
shared-файлы не меняет.
