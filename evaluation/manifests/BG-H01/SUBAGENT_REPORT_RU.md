# BG-H01 — отчёт подагента о реализации

## Объём и граница

В изолированной ветке реализована только отложенная фикстура `BG-H01` класса
`prop_reset` — сброс локального черновика при смене входной идентичности. Перед
работой полностью прочитаны `AGENTS.md`, обязательные контракты проекта,
`docs/PROJECT_SPEC.md`, `docs/EVALUATION.md`, `config/topic.yaml`, а затем только
утверждённые замороженные материалы и публичное происхождение `BG-H01` и `BG-H02`.
Внешние рабочие области, глобальная память, браузер, подключённые приложения,
приватные MCP-ресурсы, Claude и закрытые материалы других пар не использовались.

Существующие замороженные файлы поведения, происхождения и карточка владельца не
изменялись. Общие реестры, задачи, `package.json`, сценарии npm, общий индекс
контрольных сумм, интеграционные тесты, документация и журнал улучшений также не
изменялись.

## Реализованное поведение

Публичный пакет задаёт проверяемые типы входных свойств, действий и наблюдений,
минимальную отрисовку, jsdom-harness — изолированную среду React в jsdom — и единый
источник пяти видимых проверок. Явная ревизия родительского перехода отделяет
повторную отрисовку той же карточки от смены `cardId` без часов и таймеров.

Созданы ровно два нейтрально названных кандидата. Один сохраняет утверждённое
поведение, второй содержит только разрешённое семейство ошибки: при новой
идентичности текущие входные данные обновляются, но сигналы черновика не
сбрасываются. Соответствие нейтральных имён правильным меткам записано только в
закрытом для оцениваемых ветвей `ground-truth.json`.

Закрытый пакет содержит точный канонический сценарий, ожидаемые наблюдения,
самопроверку и отдельную capability-пробу — проверку реально предоставленных
процессу прав. Канонический сценарий проверяет монтаж `CARD-01`, редактирование,
повторную отрисовку той же идентичности, переход на `CARD-02`, возврат на
`CARD-01` и обычный сброс. Публичная проба проверяет невозможность перечислить,
прочитать, проверить наличие или получить доступ к закрытому пакету; встречная
проба закрытого процесса проверяет невозможность прочитать исходники кандидатов.

Каждый пакет и кандидат получил отдельный неизменяемый SHA-256 manifest. Итоговый
`fixture-implementation.manifest.json` связывает эти manifests с точными байтами
ранее утверждённых английского и русского описаний, freeze-записи, происхождения и
карточки владельца. Публичные и важные TypeScript API снабжены кратким английским
JSDoc; комментарии у перехода идентичности и границ прав объясняют защищаемый
инвариант.

## Команды, результаты, ошибки и исправления

1. `npm run compile` — завершено с кодом `0`. Эта ранняя проверка использовала
   доступный в исходном non-login shell компилятор и была только предварительной.
2. `node --import tsx --test evaluation/arm-visible/BG-H01/visible.test.ts evaluation/verifier-only/BG-H01/self-check.test.ts evaluation/arm-visible/BG-H02/visible.test.ts evaluation/verifier-only/BG-H02/self-check.test.ts`
   — остановлено до тестов: исходный shell предоставлял Node `v18.16.1`, который
   не поддержал параметр `--import` в требуемом виде.
3. Была выполнена одна диагностическая fixture-only попытка через временный
   TypeScript loader на том же Node 18. Все четыре test-файла остановились до
   выполнения assertions с безопасной категорией `ERR_REQUIRE_ESM`, потому что
   `jsdom@30.0.1` требует утверждённый современный runtime. Временный loader сразу
   удалён и не входит в manifests или commit; исходники продукта не менялись.
4. По подтверждённой координатором безопасной команде
   `zsh -lic 'node --version'` получено `v22.22.3`. Login shell напечатал
   нерелевантные диагностические сообщения и один машинный путь; путь и полный
   шум намеренно не переносятся в этот репозиторный отчёт.
5. `zsh -lic 'npm run compile'` — код `0`, TypeScript compilation пройдена на
   утверждённом runtime и проектном TypeScript `5.9.3`.
6. `zsh -lic 'node --test evaluation/arm-visible/BG-H01/visible.test.ts evaluation/verifier-only/BG-H01/self-check.test.ts evaluation/arm-visible/BG-H02/visible.test.ts evaluation/verifier-only/BG-H02/self-check.test.ts'`
   — код `0`, суммарно `14/14` тестов: для `BG-H01` зелёные `5/5` видимых проверок
   и `2/2` закрытых самопроверки; правильное поведение принято, разрешённый
   ложно-зелёный дефект отклонён на `switch-card-02`.
7. `zsh -lic 'node --permission --allow-fs-read=evaluation/arm-visible/BG-H01 evaluation/arm-visible/BG-H01/denied-probe.mjs && node --permission --allow-fs-read=evaluation/verifier-only/BG-H01 evaluation/verifier-only/BG-H01/evaluator-denied-probe.mjs && node --permission --allow-fs-read=evaluation/arm-visible/BG-H02 evaluation/arm-visible/BG-H02/denied-probe.mjs && node --permission --allow-fs-read=evaluation/verifier-only/BG-H02 evaluation/verifier-only/BG-H02/evaluator-denied-probe.mjs'`
   — код `0`; для каждой публичной стороны `allDenied=true`, различие между
   существующим и отсутствующим закрытым путём не раскрывается, `operationCount=4`;
   для каждой стороны оценщика `allCandidateAccessDenied=true`, `operationCount=3`.

8. После создания manifests структурный JSON-разбор, пересчёт каждого файлового
   SHA-256 и итогового package digest завершились с кодом `0` и строкой
   `BG-H01_BG-H02_MANIFESTS_VERIFIED`.
9. Финальная объединённая команда `zsh -lic 'npm run compile && node --test
   evaluation/arm-visible/BG-H01/visible.test.ts
   evaluation/verifier-only/BG-H01/self-check.test.ts
   evaluation/arm-visible/BG-H02/visible.test.ts
   evaluation/verifier-only/BG-H02/self-check.test.ts'` завершилась с кодом `0`:
   compilation зелёная, повторно пройдены `14/14` тестов.

## Риски и запросы координатору

Смыслового дрейфа, раскрытия эталона, сомнительного происхождения или лицензии не
обнаружено. Официальный или оцениваемый запуск, раскрытие отложенных результатов,
модель продукта, Chromium, общий preflight и push не выполнялись. Внутренние
необработанные события нативного подагента не заявляются как экспортированная
траектория.

Для последующей общей интеграции координатору потребуется добавить `BG-H01` в
shared registry/tasks, общий индекс контрольных сумм и интеграционные проверки
manifest/physical-isolation. Это только запрос; ни один shared-файл данным commit
не меняется.
