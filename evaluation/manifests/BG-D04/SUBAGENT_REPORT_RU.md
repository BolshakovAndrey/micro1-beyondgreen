# BG-D04 — отчёт встроенного дочернего агента (`native subagent`)

**Дата:** 2026-08-30<br>
**Фикстура:** `BG-D04`<br>
**Класс поведения:** `subscription_cleanup` — очистка подписки<br>
**Статус:** локальная реализация фикстуры и проверки завершены; официального или оцениваемого запуска не было

## Гипотеза

Зелёные компиляция и видимые унаследованные тесты (`legacy tests`) могут не заметить устаревшую подписку после переключения канала. Если React-to-signals кандидат — миграция React-состояния на сигналы — не возвращает функцию очистки (`cleanup`) из `useEffect`, публикация из старого канала способна обновить панель выбранного канала. Независимый проверяющий эталон (`oracle`) должен принять сохраняющий поведение кандидат и отклонить ложно-зелёный (`false-green`) кандидат именно по семейству инвариантов очистки подписки.

## Выполненные изменения

- Проверен замороженный контракт, в котором поведение описано до кода (`behavior-first`), для синтетической панели бюллетеней `harbor`/`orchard` и его SHA-256.
- Публичный пакет оцениваемой ветви (`arm-visible`) содержит типизированный источник подписок, тестовую оснастку (`harness`) jsdom/React и четыре неизменных видимых утверждения.
- Оба кандидата используют уже замороженный `@preact/signals-react@3.12.0` с лицензией MIT. Сохраняющий (`preserving`) кандидат снимает предыдущую подписку при смене канала и при размонтировании (`unmount`). False-green кандидат намеренно не снимает её; это единственное семейство внесённого дефекта.
- Закрытый пакет проверяющего эталона (`verifier-only`) содержит точный исполнитель канонического сценария (`canonical driver`), правильные метки (`ground truth`) и самопроверку (`self-check`). Он принимает preserving кандидат и отклоняет false-green кандидат с `behaviorClass: "subscription_cleanup"` на `step-2`, где после переключения должна исчезнуть подписка `harbor`.
- Проверка разрешений (`permission probe`) запускает отдельный Node-процесс с чтением только `candidates/BG-D04` и `evaluation/arm-visible/BG-D04`; чтение `evaluation/verifier-only/BG-D04/ground-truth.json` физически запрещено.
- Манифесты SHA-256 фиксируют arm-visible пакет, verifier-only пакет и оба кандидата. Fixture-runner — локальный исполнитель проверок фикстуры — сверяет контрольную сумму (`digest`) поведения и все хеши (`hashes`) до и после тестов, поэтому выполнение проверок не может незаметно изменить замороженные входы.
- Исправлено строго локальное сужение типа `textContent`: отсутствие DOM-узла теперь отклоняется с безопасным закрытием (`fail-closed`) как `null` или `undefined`.

## Команды и результаты

1. Первичная компиляция:

   ```bash
   npm run compile
   ```

   Результат: `FAIL`. TypeScript сообщил `TS2322` в `evaluation/arm-visible/BG-D04/harness.ts`: значение `bulletin` имело тип `string | undefined`. Исправлен только fixture-local harness и обновлён его hash в manifest.

2. Компиляция после локального исправления:

   ```bash
   npm run compile
   ```

   Результат: `PASS`, exit code `0`.

3. Первичная попытка fixture-runner:

   ```bash
   node scripts/BG-D04-verify.mjs
   ```

   Результат: инфраструктурный `FAIL` до выполнения тестовой логики. Активный `node` оказался `v18.16.1` и вернул `ERR_UNKNOWN_FILE_EXTENSION` для `.ts`. Кандидаты и oracle этой попыткой не оценивались; повтор той же команды на Node 18 не выполнялся.

4. Замороженный runtime и полный fixture-local прогон:

   ```bash
   test -x "$NVM_BIN/node" && "$NVM_BIN/node" --version && "$NVM_BIN/node" scripts/BG-D04-verify.mjs
   ```

   Результат: Node `v22.22.3`, `PASS`, 7/7:

   - видимый унаследованный контроль: 4/4, каждый тест прошёл для preserving и false-green кандидатов;
   - принятие preserving кандидата проверяющим эталоном: 1/1;
   - отклонение false-green кандидата с правильной причиной: 1/1;
   - физический запрет доступа к verifier-only: 1/1;
   - behavior, arm-visible, verifier-only и candidate hashes совпали до и после выполнения.

5. Финальная компиляция на замороженном runtime:

   ```bash
   "$NVM_BIN/node" "$NVM_BIN/npm" run compile
   ```

   Результат: `PASS`, exit code `0`.

## Ограничения и границы

- В изолированном рабочем дереве (`worktree`) до работы дочернего агента уже находился незакоммиченный локальный черновик BG-D04. Дочерний агент провёл самостоятельную проверку, исправил обнаруженные локальные дефекты фикстуры и завершил доказательства; чужие worktree и основная рабочая копия (`checkout`) не читались и не изменялись.
- `TRC-BG-D04-001` и `TRC-BG-D04-002` остаются неиспользуемыми неудачными попытками. Nested Codex CLI не запускался. Внутренние raw-события native subagent не заявляются как submission trace.
- Shared registry, `package.json`, lockfile, `tsconfig`, `src/d01`, общие документы, индексы, checksums и другие fixtures не изменялись.
- Не выполнялись official/scored run, benchmark, unblinding, live model, Claude, Chromium, browser, MCP, connected apps, commit или push.
- Приватный denylist и внешнее хранилище raw traces не читались; scanner/preflight с приватными значениями не запускался.
- Общая регистрация BG-D04 в shared orchestration остаётся задачей отдельной integration/review trajectory координатора.

## Итоговое решение

Fixture-local пакет готов к интеграционной проверке. Он сохраняет публичный контракт, доказывает зелёный visible gate для обоих immutable кандидатов, принимает preserving кандидат, reason-correct отклоняет false-green кандидат по очистке подписки, физически изолирует verifier-only ground truth и подтверждает неизменность frozen bytes. Shared integration в этом subagent-этапе намеренно не выполнялась.
