# BG-H04 — отчёт дочернего агента по реализации

## Результат

Фикстура `BG-H04` реализована строго по одобренной заморозке условного жизненного
цикла. Публичная часть содержит типизированный контракт, минимальную React/jsdom-
обвязку, отдельный счётчик жизненного цикла, DOM-проекцию и четыре видимые проверки
первого цикла. Созданы ровно два нейтрально названных кандидата `candidate-a` и
`candidate-b`; mapping, то есть соответствие правильному и ложно-зелёному поведению,
находится только в `evaluation/verifier-only/BG-H04/ground-truth.json`.

Закрытый канонический сценарий проверяет исходное физическое отсутствие карточки,
первое поколение, локальный черновик, одну очистку, изменение родительской заметки в
неактивном состоянии, свежее второе поколение и финальные счётчики `2/2/0`.
Самопроверка принимает правильное поведение и отклоняет скрытый живой экземпляр.
Две отдельные permission-пробы подтверждают взаимный запрет доступа между публичной
частью/кандидатами и закрытым эталоном. Предварительных подсказок эталона не было:
`K=0`.

## Точные команды, ошибка и исправление

1. `node --version && npm --version && npm run compile` — системный Node `v18.16.1`,
   npm `9.5.1`, компиляция прошла; TypeScript-тесты на этом runtime не запускались.
2. Первый прогон замороженным Node `v22.22.3` командой
   `"$NVM_BIN/node" "$NVM_BIN/npm" run compile && "$NVM_BIN/node" --test evaluation/arm-visible/BG-H03/visible.test.ts evaluation/verifier-only/BG-H03/self-check.test.ts evaluation/arm-visible/BG-H04/visible.test.ts evaluation/verifier-only/BG-H04/self-check.test.ts`
   дал `11/12`: все четыре видимые проверки H04 и отклонение `candidate-b` прошли,
   но `candidate-a` был отклонён на `edit-draft-check`. Причина: функция изменения
   черновика хранилась в переменной одного рендера и терялась после следующего.
3. Исправлен только `candidates/BG-H04/candidate-a/AstronomyChecklist.ts`: функция
   помещена в стабильный React `useRef`, а binding обёрнут в `useCallback`. Повтор
   той же команды прошёл: компиляция и `12/12`, включая все шесть проверок H04.
4. `"$NVM_BIN/node" --permission --allow-fs-read=evaluation/arm-visible/BG-H04 evaluation/arm-visible/BG-H04/denied-probe.mjs` — `allDenied=true`, четыре операции запрещены.
5. `"$NVM_BIN/node" --permission --allow-fs-read=evaluation/verifier-only/BG-H04 evaluation/verifier-only/BG-H04/evaluator-denied-probe.mjs` — `allDenied=true`, три операции запрещены.
6. После уточнения координатора команда `zsh -lic 'node --version'` подтвердила
   `v22.22.3`. Финальные `npm run compile` и четыре fixture-local тестовых файла
   повторены через login shell: компиляция и `12/12` прошли. Shell напечатал
   не влияющие на результат предупреждения `monitor` и
   `gitstatus failed to initialize`; exit code проверки был `0`.
7. Permission-пробы повторены через `zsh -lic`; для H04 снова получены
   `allDenied=true` с четырьмя и тремя запрещёнными операциями соответственно.
8. Финальная ревизия обнаружила, что наблюдение после `unmount-parent` сохраняло
   только счётчики. Локальная обвязка теперь также сохраняет актуальную родительскую
   заметку и добавляет `unmount-parent` в журнал; закрытый канонический исполнитель
   это проверяет. После изменения полный набор повторён через `zsh -lic`:
   компиляция, `12/12` и все четыре permission-пробы прошли.

Перед фиксацией хешей candidate-local комментарии сделаны нейтральными, чтобы
правильная метка не раскрывалась за пределами `verifier-only`; поведение не менялось.

## Границы и запрос координатору

Общие registry/tasks, `package.json`, package scripts, общий checksum index,
integration tests, документы и чужие фикстуры не менялись. Координатору необходимо
отдельно зарегистрировать H04 в shared orchestration, добавить общий checksum index
и интеграционные проверки. Не выполнялись официальный или оцениваемый запуск,
unblinding, живая модель продукта, Claude, Chromium, browser/private MCP, приватные
данные, общий preflight или push. Внутренние необработанные события дочернего агента
не заявляются как экспортированная трасса.
